# Technical Architecture & Implementation Handoff: Native Arabic Root-Tree Foundation Model

**Project**: Dynamic, Interactive, Knowledge-Adaptive Arabic Learning Engine  
**Target Scope**: Classical Arabic (الفصحى التراثية) & Modern Standard Arabic (MSA)  
**Primary Deliverable**: Foundation Architecture Specification, Data Pipeline, Training Strategy, and Mobile Deployment Protocol  

---

## 1. Executive Summary & Core Objective

Traditional Large Language Models (LLMs) process text as linear, 1D sequences of subword tokens, attempting to predict subsequent characters based on statistical frequency. For Semitic languages—specifically Classical Arabic and Modern Standard Arabic—this linear paradigm causes systematic failure modes:
1. **Diacritic Blindness**: Frequent misplacement of terminal case vowels (*I'rab*).
2. **Morphological Fragmentation**: Arbitrary slicing across roots and vocalic patterns.
3. **Post-Hoc Hallucination**: The need to reverse-engineer roots (*Juthūr*) and patterns (*Awzān*) from surface words after generation.

This handoff provides the end-to-end specifications for building a **Native Arabic Root-Tree Model**. Rather than generating surface letters first, the model plans at the level of the **semantic root graph**, resolves **syntactic dependency relations (العوامل والمعمولات)**, applies **morphological templates (الأوزان الصرفية)**, and renders fully vocalized, morphologically transparent text with guaranteed grammatical consistency.

## 2. Core Architectural Framework

```
+-----------------------------------------------------------------------------------+
|                           STEP 1: PEDAGOGICAL CONTROLLER                          |
|             Inputs: Learner Proficiency Level, Active Vocabulary, Grammar Goal    |
+-----------------------------------------+-----------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                     STEP 2: MACRO-SYNTACTIC ROOT GENERATOR                        |
|   Generates an Order-Free Dependency Graph of 3-Letter Roots & Syntactic Roles   |
|   Example: [Root: ك-ت-ب (Action)] ---Subject---> [Root: ط-ل-ب (Agent)]             |
+-----------------------------------------+-----------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                   STEP 3: TEMPLATIC BINDING & SARF REALIZER                       |
|   Binds Roots into Awzān via Algebraic Tensor Product Representations (TPR)       |
|   Root (ك-ت-ب) + Wazan (فَعَلَ) -> كَتَبَ | Root (ط-ل-ب) + Wazan (فَاعِل) -> طَالِب   |
+-----------------------------------------+-----------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|               STEP 4: PHONOLOGICAL & SYNTACTIC CASE INFLECTION (NAHW)             |
|   Applies Case Endings based on Directed Dependency Edges                         |
|   Fa'il -> Damma (الطَّالِبُ) | Maf'ul -> Fatha (الدَّرْسَ)                           |
+-----------------------------------------+-----------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                   STEP 5: STRUCTURED JSON DELIVERY TO MOBILE APP                  |
|   Text + Word-by-Word Breakdown (Tashkeel, Root, Wazan, Meaning, Full I'rab)      |
+-----------------------------------------------------------------------------------+
```

### 2.1 The 3D Geometric Root Manifold ($\mathcal{M}_{\text{root}}$)
In place of a standard flat 1D embedding table $V \in \mathbb{R}^{|V| \times d}$, the root lexicon is modeled as a 3D coordinate tensor:
$$\mathcal{M}_{\text{root}} \in \mathbb{R}^{28 \times 28 \times 28 \times D_{\text{root}}}$$

* **Coordinate Indexing**: Every root is represented as an ordered triple $(C_1, C_2, C_3)$ of consonant IDs from the 28-letter alphabet.
* **Lexical Sparsity**: Out of $28^3 = 21,952$ possible combinations, only $\approx 6,500$ valid roots exist in the classical lexicon (*Lisān al-'Arab*). Invalid combinations are masked out during training.
* **Semantic Topology**: Roots sharing radical phonetic features (*Makhārij al-Hurūf*) sit in contiguous manifold regions, naturally capturing **الاشتقاق الأكبر** (semantic affinities between consonant permutations).

### 2.2 Algebraic Morphological Tensor Binding
A surface word vector $\mathbf{v}_{\text{word}}$ is generated by an algebraic binding operation over distinct linguistic planes:
$$\mathbf{v}_{\text{word}} = \mathbf{W}_{\text{proj}} \Big( \mathbf{e}_{\text{root}}(C_1, C_2, C_3) \odot \mathbf{e}_{\text{wazan}}(W) \odot \mathbf{e}_{\text{clitics}}(K) \Big) + \mathbf{e}_{\text{pos}}(\text{POS}) + \mathbf{e}_{\text{case}}(\text{Case})$$

* **$\mathbf{e}_{\text{root}}$**: Vector representation from the 3D root space.
* **$\mathbf{e}_{\text{wazan}}$**: Vector representation from the finite catalog of $\approx 70$ primary verbal and nominal patterns (*فَعَلَ، أَفْعَلَ، فَاعَلَ، فَعَّلَ، تَفَعَّلَ، تَفَاعَلَ، اسْتَفْعَلَ، فُعُول، فَعِيل، مَفْعُول...*).
* **$\mathbf{e}_{\text{clitics}}$**: Discrete multi-hot encoding of attached particles (conjunctions, prepositions, future marker, attached pronouns).
* **$\mathbf{e}_{\text{case}}$**: Syntactic inflection vector (*Raf', Nasb, Jarr, Jazm*).

## 3. Data Engineering & Corpus Requirements

### 3.1 Primary Curated Datasets
To supervise both the macro-syntactic tree and the micro-morphological binding, compile the following corpora:

1. **[The Quranic Arabic Corpus](https://corpus.quran.com/) (University of Leeds)**:
   * Provides gold-standard token-by-token annotation: surface form, lemma, 3-letter root, exact morphological pattern, POS tag, and full traditional syntactic dependency graph (*I'rab*).
2. **Prague Arabic Dependency Treebank (PADT) / Universal Dependencies (UD Arabic)**:
   * Over 27,000 sentences annotated with syntactic heads, dependency relations, and lemmatized roots.
3. **Classical Lexical Bases**:
   * Machine-readable exports of *Al-Mu'jam al-Wasīt*, *Lisān al-'Arab*, and *Hans Wehr* for ground-truth root-to-definition mappings.
4. **Tashkeela & Diacritized MSA Corpora**:
   * For pretraining the surface phonological generation engine across over 75 million vocalized words.

### 3.2 Morphologically-Aware Tokenization ([MorphBPE](https://arxiv.org/abs/2502.00894))
* **Algorithm**: Implement MorphBPE boundary constraints.
* **Rule**: Split words into pre-segmented morphological units (`Prefixes + Stem + Suffixes`) using [CAMeL Tools](https://github.com/CAMeL-Lab/camel_tools) before running BPE merges.
* **Vocabulary Size**: 32,768 to 48,000 tokens.
* **Partitioning**:
  * 28 single consonants and short vowels.
  * 120 common clitics and affixes (`و+`, `ف+`, `ب+`, `ك+`, `ل+`, `ال+`, `س+`, `+هم`, `+هن`, `+كما`).
  * 6,500 canonical 3-letter roots.
  * 70 canonical templatic patterns (*Awzān*).
  * High-frequency non-derived closed-class words (pronouns, demonstratives, particles: *هذا، ذلك، الذين، حيث، إلا*).

## 4. Multi-Task Training Objectives

The training objective enforces grammatical compliance via explicit auxiliary heads, preventing the model from relying on surface statistical co-occurrence.

$$\mathcal{L}_{\text{Total}} = \mathcal{L}_{\text{NTP}} + \lambda_1 \mathcal{L}_{\text{Root}} + \lambda_2 \mathcal{L}_{\text{Wazan}} + \lambda_3 \mathcal{L}_{\text{Syntax}} + \lambda_4 \mathcal{L}_{\text{Case}}$$

```
                                [ Transformer Latent Hidden State h_t ]
                                                   |
      +--------------------+-----------------------+-----------------------+--------------------+
      |                    |                       |                       |                    |
      v                    v                       v                       v                    v
  Head 1 (NTP)        Head 2 (Root)          Head 3 (Wazan)        Head 4 (Syntax)       Head 5 (Case)
Predict Next Lemma    Predict (C1, C2, C3)    Predict Pattern ID    Predict Dep Role      Predict Final Vowel
[Next-Token Loss]     [3D Cross-Entropy]      [Multi-Class CE]     (Fa'il / Maf'ul)     (Damma/Fatha/Kasra)
```

1. **Next-Token Cross-Entropy ($\mathcal{L}_{\text{NTP}}$)**: Standard language modeling loss over morphological stems.
2. **Root Auxiliary Loss ($\mathcal{L}_{\text{Root}}$)**: Multi-label classification over the 3-letter coordinate space $(C_1, C_2, C_3)$.
3. **Pattern Auxiliary Loss ($\mathcal{L}_{\text{Wazan}}$)**: Multi-class classification over the 70 morphological templates.
4. **Syntactic Dependency Loss ($\mathcal{L}_{\text{Syntax}}$)**: Biaxial attention loss predicting head position and dependency label (*'Amil & Ma'mul*).
5. **Terminal Case-Marker Loss ($\mathcal{L}_{\text{Case}}$)**: Categorical loss predicting the final diacritic mark (*Damma, Fatha, Kasra, Sukun*).

## 5. Mobile Runtime & Edge Deployment Protocol

For a responsive mobile app (Android/iOS), the inference stack must maintain sub-100ms latency without requiring internet connectivity.

### 5.1 Model Footprint & Sizing Budget
* **Target Size**: 1.1B to 1.5B parameters.
* **Precision / Quantization**: 4-bit Medium Quantization (`Q4_K_M` GGUF or `int4` ExecuTorch format).
* **RAM Allocation**: ~1.1 GB memory footprint on device.
* **Supported Frameworks**:
  * **iOS**: ExecuTorch / Apple CoreML (utilizing the Apple Neural Engine).
  * **Android**: `llama.cpp` mobile runtime / MLC-LLM / Snapdragon NPU acceleration.

### 5.2 Deterministic Output Schema via Constrained Decoding
To ensure the mobile UI parses generated paragraphs seamlessly into interactive clickable words, enforce a **GBNF (Grammar-Based Backus-Naur Form)** grammar during decoding.

#### Grammar Specification (`arabic_learner.gbnf`):
```gbnf
root ::= "{" ws "\"paragraph\":" ws string "," ws "\"analysis\":" ws "[" ws (word_item ("," ws word_item)*)? ws "]" ws "}"

word_item ::= "{" ws 
  "\"word\":" ws string "," ws 
  "\"tashkeel\":" ws string "," ws 
  "\"root\":" ws string "," ws 
  "\"wazan\":" ws string "," ws 
  "\"meaning\":" ws string "," ws 
  "\"irab\":" ws string 
ws "}"

string ::= "\"" [^\"]* "\""
ws ::= [ \t\n\r]*
```

### 5.3 Hybrid Local Verification (Zero-Hallucination Fallback)
Deploy an embedded SQLite database (~45 MB) on the mobile device containing:
* Canonical roots and verified lemma translations.
* A trie dictionary of weak verb irregularities (*I'lāl and Ibdāl*).
* If the neural model outputs a confidence score $< 0.85$ on a root or case-marker, the local deterministic trie automatically overrides and corrects the entry before rendering.

## 7. Reference Implementation: Multi-Plane Root & Pattern Layer

Below is the foundational PyTorch module implementing the multi-plane tensor binding:

```python
import torch
import torch.nn as nn

class ArabicMorphologicalEmbedding(nn.Module):
    """
    Multi-plane embedding module binding Root, Wazan, Clitics, and POS into a single representation.
    """
    def __init__(self, embed_dim=1024, num_consonants=29, num_awzan=75, num_pos=45):
        super().__init__()
        self.embed_dim = embed_dim
        
        # 1. Radical Consonant Embeddings (C1, C2, C3)
        self.c1_emb = nn.Embedding(num_consonants, embed_dim // 3)
        self.c2_emb = nn.Embedding(num_consonants, embed_dim // 3)
        self.c3_emb = nn.Embedding(num_consonants, embed_dim // 3 + embed_dim % 3)
        
        # 2. Templatic Pattern (Wazan) Embedding
        self.wazan_emb = nn.Embedding(num_awzan, embed_dim)
        
        # 3. Morphosyntactic Features (POS & Grammatical Role)
        self.pos_emb = nn.Embedding(num_pos, embed_dim)
        
        # 4. Fusion and Gating Projection
        self.fusion = nn.Sequential(
            nn.Linear(embed_dim * 2, embed_dim),
            nn.LayerNorm(embed_dim),
            nn.GELU(),
            nn.Linear(embed_dim, embed_dim)
        )

    def forward(self, c1_ids, c2_ids, c3_ids, wazan_ids, pos_ids):
        # Concatenate 3 consonants to form root vector
        e_root = torch.cat([
            self.c1_emb(c1_ids),
            self.c2_emb(c2_ids),
            self.c3_emb(c3_ids)
        ], dim=-1)
        
        # Pattern and POS representations
        e_wazan = self.wazan_emb(wazan_ids)
        e_pos = self.pos_emb(pos_ids)
        
        # Multiplicative interaction (Hadamard binding) between Root and Wazan
        bound_morpheme = e_root * e_wazan
        
        # Fuse with grammatical POS tag
        token_representation = self.fusion(torch.cat([bound_morpheme, e_pos], dim=-1))
        return token_representation
```
